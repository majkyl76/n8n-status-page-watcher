# Final review 2 — independent adversarial pass

Scope: SPEC.md AC1–AC19, with focus on the last five commits (body-cap /
footer shrink in `renderBodies`, the resolved-after-resolved guard, the
AC13 property-test reference model, and the licence lint check). `npm test`
passes 110/110 and `npm run lint:copy` reports 0 issues going in; the
findings below are gaps those suites don't exercise. All probes live under
`scratch/` (throwaway, not part of the shipped test suite) and were run with
`node scratch/<file>.mjs` from the repo root against the real
`src/detect-incidents.js` as shipped in `workflow.json`.

| ID | Severity | What is wrong | Exact command and output proving it | Suggested fix |
|---|---|---|---|---|
| F1 | **Blocker** | `renderBodies` (src/detect-incidents.js:278-292) claims in its own comment that the footer "is never silently lost", but its last-resort fallback (`hardCutText`/`hardCutHtml`) slices the **whole already-rendered string** (header + event + footer) from the front. Since the footer line is appended last, any time the single remaining shown event's rendered text alone is at or past `MAX_BODY_CHARS`, the slice lands before the footer and the "+N more events not shown" line is dropped entirely (or occasionally left mid-sentence). This is exactly the AC10/review-F1 guarantee the latest commit (184c56b) was meant to deliver, and it fails in the one case the commit added code for. | `node scratch/probe-footer-loss.mjs` → `text length: 19999` / `footer says hidden = null (actual incidents besides shown huge one = 5)`. A second, more realistic trigger needs no 20k-char title at all: `node scratch/probe-footer-loss3.mjs` → with a 6500-character `&` incident name (plausible from a hostile/misbehaving vendor page), `text length 6790 has footer: true` but `html length 19997 has footer: false` — the HTML body (the one most mail clients render) silently loses the disclosure while the plain-text body is fine. | In the fallback branch, don't hard-cut the finished string. Compute the header and footer text/HTML first, reserve their length, then hard-cut only the one event's own rendered fragment to fit the remaining budget, and reassemble header + cut-event + footer. That keeps the footer intact in every case, matching the existing comment's stated intent. |
| F2 | **Major** | The main loop treats any own-key entry in `ps.incidents` as a valid state record without checking its shape: `const prev = Object.hasOwn(ps.incidents, id) ? ps.incidents[id] : undefined;` followed directly by `prev.updatedAt`/`prev.status` in the "known incident" branch. A `null` (or any non-object) value for an id — e.g. workflow static data carried over from an older/different schema, or a hand-edited/partially-written state — throws inside the Code node. Because this node runs once for *all* pages, the whole run aborts and produces no output for any page that execution, not just the one with bad state, breaking the explicit "one broken page never stops the others" guarantee. | `node scratch/probe-null-state-entry.mjs` with `staticData.pages['https://x.example'].incidents = { a: null }` and a matching incoming incident `a` → `CRASHED: Cannot read properties of null (reading 'updatedAt')`. | Guard the "known incident" branch: `if (!prev || typeof prev !== 'object') { /* treat like first-seen, or skip/reset this entry */ }` before reading its fields, instead of only checking `prev === undefined`. |
| F3 | Minor | `LICENSE_NOUN_RE` in `scripts/lint-lib.mjs` (added in 184c56b) under-matches noun usage of "license": it only tolerates a determiner plus **one** optional word before the noun, and requires a determiner/possessive/"MIT" at all. Real prose regularly has more than one adjective, or opens a sentence/heading with the noun and no determiner. | `node scratch/probe-lint-license.mjs` → `"This has a permissive open source software license." => []` and `"License terms are at the end." => []` (both should flag, per AC12's "licence (noun)" rule; compare to the already-passing cases in `tests/copy.test.mjs` which only use single-adjective, determiner-led phrasing). Currently harmless: `grep -in "licen[sc]e" README.md LISTING.md workflow.json` finds no hits, so `npm run lint:copy` is unaffected today, but the check is an incomplete implementation of the AC12 requirement and would silently miss these in future edits. | Invert the heuristic: flag bare "license"/"licenses" as the noun by default, and only *exempt* it when immediately preceded by "to" or a modal/auxiliary verb ("will", "may", "can", "must", "to") that marks verb usage — a short exemption list is easier to keep complete than enumerating every noun-context pattern. |
| F4 | Minor (informational) | `renderBodies` is O(n²) in the number of events that end up shown: each shrink step re-renders the entire remaining list from scratch via `renderText`/`renderHtml`. Not a correctness bug, and SPEC.md sets no latency budget, but it is the kind of thing that degrades badly under the "performance with 500 incidents" adversarial scenario this review was asked to check. | `node scratch/probe-perf.mjs` (500 incidents, `maxIncidentsPerPage: 500`, ~150-char update bodies) → `time ms 715` for one page in a single Code-node execution. | If this matters in practice, binary-search `shownCount` instead of decrementing by one, or compute incremental lengths instead of re-rendering the full list each step. Not blocking given no stated perf requirement. |

## Spec gaps / honesty check

- AC10's own text ("...so the footer is never silently lost...") is not met in the fallback path — see F1. This is a direct, provable spec violation, not a style nit.
- VERIFICATION.md marks AC10 "pass" on the strength of `npm test`; that's accurate as far as the suite goes, but the suite's one footer/shrink test (`tests/email.test.mjs`, the "realistic multi-incident page" test added alongside the fix) only uses incidents small enough that the hard-cut fallback is never reached, so it cannot catch F1. The property test (`tests/property-golden.test.mjs`) also can't catch it: its generator uses short fixed incident names ("Incident a/b/c") and never produces an oversized single event. Both suites currently pass **vacuously** with respect to F1.
- Test counts, AC-to-file mapping, and the copy/sticky/README/LISTING cross-checks (AC2, AC3, AC5, AC11, AC12) all check out: `npm test` reports 110/110 as quoted in NOTES.md/VERIFICATION.md, `npm run lint:copy` reports 0 issues, `workflow.json` rebuilds identically from `src/` (no stale-artefact drift), and no secrets, real hostnames or personal details were found in README.md, LISTING.md or workflow.json.
- AC15/AC16 (resolved-after-resolved, out-of-order timestamps) and the property-test reference model were checked line-by-line against `src/detect-incidents.js`'s equivalent logic (timestamp comparison branches, the `!isResolved(prev.status)` re-alert guard) and found to match; no discrepancy between model and implementation was found there.

## Verdict

**FAIL** — F1 is a provable, directly-spec-contradicting defect in exactly the code path the last commit was written to fix (AC10, review F1's own stated guarantee), and F2 is a real crash that can zero out an entire run's output. Both need a fix and a regression test (one with a single oversized event/HTML-escaped event alongside smaller ones so the footer must survive the fallback path, and one with a malformed/old-shape `ps.incidents` entry) before this ships.
