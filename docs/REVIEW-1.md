### Spec gaps / notes
- **Spec self-contradiction behind F2.** The resolution rule ("sent only if previously alerted **OR passes the filter now**") directly conflicts with AC6's "Already-resolved incidents seen for the first time are history: … never alert." The `|| passes` clause is exactly what lets history alert. The spec should say the resolution alert requires a genuine notified open→resolved transition, not merely "passes now."
- **`initialised` is dead state.** It is written (`detect-incidents.js:340`) but never read; no logic depends on first-run vs later. Spec keeps the field but it drives nothing — harmless, but worth noting it does not gate any behaviour.
- **`responseFormat: "json"` + non-JSON body (UNPROVEN in real n8n).** The HTTP node is set to parse JSON; a 200-with-HTML or a 404-with-HTML body will make n8n raise a parse error rather than deliver a string body. With `onError: continueRegularOutput` that becomes an error item, which `detect` handles via `resp.error`, so the outcome (a failure) should still be correct — but this path differs from how the unit tests model it (`statusCode !== 200`), and I could not run a live n8n to confirm the error-item shape. Recommend the PM-run `npm run e2e` exercise the HTML-body case.
- **Label containing `|`** throws ("Cannot read a status page URL…") because only the first `|` splits label from URL. Acceptable given the documented `Label | URL` format, but undocumented.
