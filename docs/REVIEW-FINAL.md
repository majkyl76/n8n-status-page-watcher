## Spec gaps

- The spec never states what should happen when the mandatory `"+N more events not shown"` notice itself would be pushed past the 20000-character body limit (F1). `maxIncidentsPerPage` also has no documented upper bound, which is what makes F1 reachable with realistic per-event sizes.
- AC17's surrogate-pair safety is specified only for the subject (149-char cut) and the per-update 500-char truncation. The full-body 19999-char cut (`MAX_BODY_CHARS`) has no equivalent guard (`trimLoneSurrogate` is not called there); I could not construct a realistic input that actually splits a pair at that specific boundary, but the code path is unprotected by inspection, unlike the other two cut sites.
- `ignoreIncidentsOlderThanHours` is documented (NOTES.md, README, sticky) as a storage-only bound with no effect on alerting, exactly as SPEC.md permits ("or drop the setting... tell me in NOTES.md"); this is a resolved ambiguity, not a gap, noted here only for completeness.

## Weak tests

- AC13's property test: see F2. The "independent" model is not independent, and the random generator never produces missing/invalid timestamps, so it cannot be relied on to have caught F2/F3-class bugs on its own; it is reinforcement of the hand-written example tests, not a second, differently-derived check.
- AC3's "no secrets" test (`tests/guidelines.test.mjs`) scans only `JSON.stringify(workflow)`, not README/LISTING/NOTES/samples/scripts. I grepped those by hand and found nothing, but there is no automated guard against a future leak outside `workflow.json`.
- A few AC7/AC9 tests assert only `Array.isArray(out)` / "does not throw" (e.g. "AC7: OpenAI payload with no components does not crash") rather than a specific expected value; they are legitimate crash-guards but would not catch a wrong-but-non-crashing result. This is a minor weakness, not a vacuous test (a crash would still fail it).

## Verdict

PASS, with F1 and F2 recommended as fix-before-submission items (neither is a blocker: F1 degrades gracefully under an edge-case load rather than corrupting state or crashing, and F2 is a test-suite confidence issue that extensive manual adversarial probing did not turn into an actual behavioural defect).
